# 使用手册

## 工作区与资料

每个工作区是独立 SQLite 文件，位于 `src/data/workspaces/`；它保存通用资料、论文兼容数据、处理记录和关系。主数据库只保存来源与工作区目录。`src/data/` 不进入 Git。

“资料中心”当前支持文字、用户图片、单个公开 URL 和 arXiv 公开 API 候选发现：

- 自动清理换行和多余空格，以规范化内容的 SHA-256 指纹做工作区内精确去重；
- 用本地可解释规则建议“通用、论文、求职、Debug”类型，不需要 AI；
- 标题、标签、类型和状态会写入数据库，切换页面或重启后仍保留；
- 默认搜索标题和原始正文，并按类型、状态筛选；明确勾选后还可搜索已接受的提取文本；
- 文字导入表单中的来源网址只是 provenance（出处），不会自动打开或抓取。
- 图片支持 PNG、JPEG、WebP，单文件不超过 10 MB、最长边不超过 12,000 像素、总像素不超过 4,000 万；后端完整解码并拒绝损坏、伪装、截断、超限和解压炸弹图片，再以文件 SHA-256 去重。
- 图片原件保存在 `src/data/assets/` 下的工作区隔离目录，数据库保存受控相对路径、字节数、哈希、可信解码尺寸和 provenance；预览与 OCR 前会再次验证这些事实。
- 详情页可主动运行本机 Tesseract OCR；有 `eng` 与 `chi_sim` 时同时识别中英文，只有英文包时退回英文。未安装 Tesseract 时会记录失败并提示安装，不会转用云端 OCR。
- 成功 OCR 会先显示预览。只有点击“接受此 OCR 文本”才写入独立接受层；接受层记录对应运行，不覆盖空的图片正文或删除历史运行。刷新和工作区切换后仍从当前工作区数据库读取。
- OCR 接受值默认不参与搜索。勾选“同时搜索已接受提取文本”后，本次搜索才扩展到接受层。

公开 URL 导入必须从“导入公开 URL”按钮明确发起。后端使用具名 `single_public_url` 采集器，只读取一个标准端口上的公开 HTML 页面：拒绝认证 URL 和本机/私有/保留地址，逐跳检查 DNS 与对端地址，按来源读取 robots 并对每个跳转后的路径重新判断，禁用环境代理，并限制为 3 次重定向、30 秒总耗时、1 MB 解压后 HTML。字符集按 HTTP 声明、BOM、HTML meta 的顺序严格确定；未知或错误声明会显示失败，不会用乱码创建候选。它不登录、不执行页面脚本、不下载附件。

成功提取的标题、正文、最终 URL、采集器和时间先进入候选箱，不会污染正式资料。检查摘要和来源后点击“接受入库”才创建或关联通用资料；“拒绝”会持久保存决定。失败任务及原因也会显示在候选箱。基于 JavaScript 渲染或正文结构特殊的页面可能提取不完整，此时应改用正常浏览后的文字或截图导入。

“发现 arXiv 候选”会把用户明确输入的搜索词发送到固定的 arXiv 官方公开 HTTPS API。单次只取 1–20 条摘要元数据，限制 25 秒总耗时和 2 MiB 解压后 Atom XML，不跟随重定向、不下载 PDF。搜索任务、数量和失败原因持久保存，多条结果仍只进入候选箱；接受时保存 arXiv ID、作者、分类、发布时间、采集时间和 API provenance，并映射为论文类型通用资料。应用异常退出留下的运行中采集任务会在下次启动时显示为中断失败，可由用户重新执行。普通自动测试只使用本地 Atom/HTTP fixture，不访问 arXiv。

## Debug、求职模板与本地相似检索

将文字资料保存为 Debug 类型后，详情页会使用本地标签规则提取“错误、环境、尝试、根因、最终方案”。提取值和用户确认值分层保存：输入框留空时采用本地提取值，填写并保存后采用确认值；“重新本地提取”会留下处理记录且不会覆盖确认值。

资料列表选择 Debug 类型后可按“错误”模板字段筛选。任意资料详情可点击“查找相似资料”，系统在当前工作区本地计算 token Jaccard 分数，显示共同 token 并持久保存关系证据。该功能不会调用 AI，也不会把资料发送到网络；当前属于近似文本检索，不代表同义表达的语义相似。

将招聘描述保存为求职类型后，本地标签规则会提取“公司、岗位、地区、薪资、技能、经验年限、投递状态”。详情使用与 Debug 相同的分层交互：输入框只保存用户确认值，下方始终显示本地提取值，确认值优先成为当前有效值；重新提取会新增审计运行并保留确认值。选择求职类型后可按公司、岗位和投递状态筛选，三个条件可与资料状态组合，筛选也遵循确认值优先。

两个模板共用注册、API 调度、字段渲染和确认优先筛选机制，但各自的字段与标签规则独立。规则只读取当前资料原文，不推断缺失信息、不调用外部 AI。自由叙述、别名或复杂排版可能提取为空，此时可直接填写确认值。求职模板不是招聘采集器，不访问招聘网站、操作账号、提交表单或自动投递。

## 行动专题：从证据到下一步

在资料中心勾选 1–20 条当前工作区资料后，点击“建立行动专题”。创建对话框会显示精确证据 ID 和标题；用户填写专题标题、目标、笔记/当前结论和明确下一步。创建成功后进入独立“行动专题”页面。

行动专题具有进行中、已完成和已归档三种状态。证据清单有明确顺序，可以上下移动、移除，也可以通过本地资料搜索追加新证据，最多 20 条且至少保留一条。点击证据标题会回到对应资料详情。专题、证据顺序和用户文字属于当前工作区，刷新、切换工作区和完整归档往返后仍保留；创建或替换清单前会一次验证全部资料归属，不能跨工作区引用相同 ID。

专题层不复制资料正文，不修改来源、资产、确定性提取、AI 运行或用户确认值。当前第一阶段没有专题 AI 自动综合：这是刻意保留的边界，先确保用户结论和下一步是主数据；后续增强也必须让用户明确确认证据范围并将 AI 输出保存为独立建议。

“清空工作区”会同时清除行动专题、通用资料、论文兼容数据和当前工作区的图片资产；删除非当前工作区时也只删除该工作区数据库及其隔离资产目录。操作前应在“切换工作区”对话框点击“导出完整归档”。生成的 `.researchmate.zip` 包含一致的 SQLite snapshot、manifest、行动专题和数据库引用的全部图片，不包含全局设置、API Key 或日志。

导入完整归档会验证版本、成员路径、文件数量、解压后大小、数据库完整性，以及每张图片的哈希、实际格式与尺寸；成功后为新数据库路径建立独立资产目录并切换到导入工作区。压缩文件最大 512 MB，解压后最大 512 MB，数据库最大 100 MB，最多 1,000 张图片且单张仍不超过 10 MB。旧 `.db` 仅兼容没有图片记录的工作区；含图片记录的裸数据库会明确拒绝，必须从原工作区重新导出完整 ZIP。

## 论文来源同步

默认支持 arXiv category/list URL，并使用 arXiv 公共 API，而不是模拟浏览器抓页面。保存标题、作者、摘要、分类和链接，不默认下载原文文件。

每条兼容论文记录通过 `papers.item_id` 幂等映射到通用资料，因此论文摘要也能在“资料中心”搜索、筛选并参与显式 M2 AI；“论文中心”、购物车和论文字段仍保留。若相同内容指纹已存在，映射会复用已有资料且不覆盖用户标题、类型、标签或状态。

- “仅新论文”跳过已存在的 canonical ID/URL；
- “全部重新同步”刷新元数据，但保留收藏和已有 AI 字段；
- 通用 HTML 适配器是遗留实验能力，默认不注册；
- 新来源应使用公开 API/RSS 或具名适配器，带数量、超时、频率限制和离线 fixture 测试。

项目不会绕过登录、付费墙、CAPTCHA、robots、访问控制或限流，也不会代替用户操作招聘账号或提交表单。条款不清晰时，优先由用户正常浏览后粘贴文字或保存截图。

## AI 与 API Key

AI 是可选处理层，不是数据真相。外部调用必须由用户发起、限制输入范围，并把 AI 建议与来源事实、用户确认分开保存。

- 外部 API 是主要增强路径；DeepSeek 的离线生产契约与受控真实烟测已完成，通用资料、论文聊天和购物车论文分析已有各自可审计路径，工作区综述仍待迁移；
- 推荐用 `RESEARCHMATE_AI_TYPE`、`RESEARCHMATE_AI_KEY`、`RESEARCHMATE_AI_URL`、`RESEARCHMATE_AI_MODEL` 环境变量；
- 设置页提供两种明确的 Key 保存方式：默认“安全模式”只存在当前后端进程；“便利模式”会在警告后明文写入界面所示的 `src/backend/config.yaml`，该文件被 Git 忽略并设置为仅当前用户读写。切回安全模式或点击“清除 Key”会删除磁盘副本；API 永不把 Key 回传给浏览器；
- 浏览器只访问本机 `/api`，不会直连模型服务；
- 论文聊天按当前工作区保存会话与每轮审计；每轮最多读取明确附加的 12 篇，每篇摘要最多 1,200 字符，历史只取最近最多 10 个成功轮次且合计不超过 12,000 字符；
- 自动测试不调用真实 AI、付费接口或真实网络来源；真实 DeepSeek 只在用户明确授权后以无敏感资料、受限次数单独验收。

设置页选择 DeepSeek 后，API Base URL 和模型仍可编辑；当前预设使用 `https://api.deepseek.com` 与 `deepseek-v4-pro`。页面不会自动测试连接。点击“测试连接”会先提示这将产生一次可能计费的外部请求，然后仅发送固定最小提示，不发送工作区资料；该测试显式关闭 DeepSeek 思考并使用有界的 64 token 输出额度。DeepSeek 的结构化 JSON 任务同样关闭思考，开放式聊天保留服务商默认。401、余额/额度、模型不存在、429、超时、5xx、空响应、截断和解析错误会转换成稳定的脱敏提示。

若希望关闭并重启 ResearchMate 后继续使用 Key，在设置中选择“便利模式”并重新保存 Key。这个选择以跨平台普通文件实现，不依赖 WSL、Windows Credential Manager 或特定桌面钥匙串。它以便利性换取本机明文风险；共享机器或高敏感 Key 应继续使用安全模式或环境变量。环境变量优先于配置文件，若界面显示 Key 来自环境变量，网页清除不会修改外部环境。

论文中心聊天会调用设置中的模型服务，但“远程模型”不等于“实时联网”。当前聊天没有网页搜索工具，只读取有界会话历史、你的当前问题与明确附加的最多 12 篇论文摘要。会话和每轮成功/失败保存在当前工作区，界面显示附加论文 ID、模型和可用 token；刷新或重启后可恢复，切换工作区不会串话。需要新网页资料时，请先使用具名 arXiv 发现或“导入公开 URL”，检查来源并接受入库后，再明确附加给 AI；系统不会让聊天模型任意浏览网站。

购物车中的论文可点击每篇“分析”，也可一次批量分析当前购物车的 1–20 篇。两种入口都会逐篇发送最多 300 字符标题和 3,000 字符摘要，并分别保存运行中、成功或脱敏失败状态、输入范围、模型、token、耗时和可用请求 ID；刷新、重启或切换工作区后会从对应工作区恢复。批量部分失败时界面会明确报告成功/失败数量并保留逐篇失败，不会显示整批成功。

购物车中的“AI 建议”只来自新的运行历史，不会写回论文标题、摘要、作者、论文链接、来源代码判断或代码链接，也不会更新旧 `papers.ai_*` 和分析标志。已有旧结果仍显示在“旧兼容结果（只读）”区域，不能当作统一审计记录。工作区综述尚在兼容路径，下一切片再迁移。

单条通用资料的分析步骤：

1. 在“资料中心”打开一条资料，在“显式 AI 分析”中选择“类型建议”或“摘要与字段提取”。
2. 勾选允许发送的标题、原始正文、已接受提取文本、当前类型、标签或来源 URL；原始正文与接受文本分别最多发送前 12,000 个字符。没有明确勾选的层不会发送。
3. 点击“确认范围并运行”。未配置模型时界面会提示前往设置页，不会制造成功记录。
4. 运行历史持久保存字段范围、输入哈希、处理器与提示词版本、服务商、配置模型、服务商返回模型、输入/输出 token、耗时、可用请求标识、状态、建议结果或脱敏错误。相同输入和相同模型的已有成功结果会直接复用；失败可重新运行。

模型响应必须通过结构校验。类型、摘要、标签和领域字段均只写入运行记录作为建议，不覆盖导入事实、本地提取或用户确认值。

多资料比较在资料列表勾选 2–20 条后发起。确认对话框显示完整资料 ID/标题清单和字段范围；每条原始正文和接受文本分别最多发送前 3,000 个字符，没有接受值的资料在该字段为空。比较结果与失败同样进入持久运行历史。

## 已知验证边界

- 真实模型服务商调用按安全规则不进入自动测试。DeepSeek 的请求形状、JSON Output、错误映射、用量审计与资料浏览器流程已有离线 fixture；另已在用户明确授权后使用独立工作区和两条无敏感资料完成分类、结构化提取与比较的三次受限真实烟测。真实响应与 fixture 契约一致，真实调用仍不进入 CI。
- 当前开发机已用 Tesseract 5.5.2 的 `eng+chi_sim` 对临时生成的无敏感中英文字图完成真实离线 OCR 验收；真实 OCR 仍不进入缺少 Tesseract 的普通 CI 环境。
- 图片自动测试使用临时工作区和临时资产目录，覆盖完整 PNG/JPEG/WebP 的导入、预览、OCR processor 输入、成功/失败审计、接受层不被失败改写和工作区隔离；不读取 `src/data/`。
- 完整工作区归档已用临时 PNG/JPEG/WebP 验证数据库、OCR/接受记录和图片往返，并覆盖篡改、缺失、孤立、路径穿越、符号链接、版本及解压边界拒绝。它是 ResearchMate 自有迁移格式，不是通用云备份或跨版本无限兼容承诺；当前格式版本为 1。
- OCR 浏览器 E2E 使用完整离线图片与 API fixture，覆盖损坏图片可见错误、成功导入与预览、OCR 失败审计和成功预览；本机 Tesseract 的真实中英文识别由后端临时资产测试单独覆盖，浏览器测试不依赖机器安装状态。
- 图片导入前会完整解码并执行字节、尺寸、总像素与解压炸弹限制；拒绝路径不会创建数据库记录、资产目录或孤立文件。落盘后被替换的资产也会在预览/OCR 前因完整性不匹配而拒绝。
- 单 URL 导入已用 `example.com` 与 `httpbin.org` 的无认证公开页面完成受控真实 DNS、TLS、robots、重定向、UTF-8 和最终内容类型验收；真实响应不会进入普通测试。离线回归覆盖逐跳 DNS、同源/跨源 robots、peer 复核、3 次重定向、解压后大小、HTTP/meta 字符集、持久失败与完整候选审核浏览器流程。
- URL 正文提取是确定性的静态 HTML 启发式，不执行 JavaScript，也不保证适配所有站点结构。
- Debug 与求职模板的离线纵向流程及共享最小模板层已实现；浏览器测试使用离线 API fixture，尚未用真实个人求职数据或招聘来源验收。
- Debug 与求职当前都只识别按行的中英文标签；自由叙述可能提取为空。薪资、年限和投递状态仍按原始文本保存，尚未规范化为可排序区间或状态枚举。
- 本地相似检索只使用词元重合，对同义改写、短文本和跨语言内容的召回有限；语义向量检索尚未实现。
- arXiv 发现已用一次 `limit=1` 的无敏感查询完成官方 API 真实 Atom 响应验收；离线回归覆盖请求参数、HTTP/内容类型/UTF-8/XML/解压后大小错误、完整候选审核、刷新、工作区隔离和启动中断恢复。真实访问不进入普通测试；RSS 和其他公开来源仍需逐个评估。
- 论文来源刷新不会静默改写已映射资料的可搜索正文或用户字段；后续需要显式、可审计的重新处理动作。
- 旧论文专用 AI 字段仍是只读兼容数据；新的购物车分析写入独立审计运行，工作区综述的旧成功结果与失败审计仍待迁移。

详细状态、编号和统一处理方法以 [ROADMAP.md](ROADMAP.md) 的集中验证与后续处理清单为准；现有 AI 路径与新旧差异见 [AI_PATHS.md](AI_PATHS.md)。

外部 AI 意味着所选内容会离开本机，可能产生费用并受服务商留存/账号政策约束。使用独立、低权限、有限额、可撤销的 Key；不要把 Key 发给 Codex 或写入代码。高敏感资料应不调用外部模型；若用户已经自行部署 Ollama，可将它作为可选后端，但 ResearchMate 不负责安装或下载本地模型。

## 新 Codex 会话如何接手

必须从仓库根目录启动 Codex。根目录 `AGENTS.md` 是自动加载的入口，它要求新会话先完整阅读 `PRODUCT.md`、`ARCHITECTURE.md`、`ROADMAP.md`，检查未提交改动，再沿 `UI → API → service → repository → SQLite` 追踪当前最小里程碑。

这套结构的分工是：

- `AGENTS.md`：稳定流程、安全规则和完成定义；
- `PRODUCT.md`：长期产品意图；
- `ARCHITECTURE.md`：不能破坏的数据与模块边界；
- `ROADMAP.md`：唯一的当前进度和下一步；
- 测试与代码：最终事实，文档冲突时先查证再修正文档。

因此无需把旧会话完整复制给新会话。若目标变化，先更新产品规格/路线图；若完成一个功能，同时更新测试和路线图。

## 代码质量与排错

新功能必须是一条可验证的纵向切片：请求模型、服务、存储、API、UI、失败状态、测试和文档一致。禁止硬编码用户路径、端口、凭证，禁止假成功、空按钮、静默异常和只保存在浏览器的关键状态。外部 I/O 放在适配器，业务规则不塞进路由；数据库迁移必须幂等并保留旧数据。
