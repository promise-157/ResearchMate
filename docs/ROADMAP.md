## 已验证基线

ResearchMate 已形成一个本地优先的个人资料闭环：

```text
导入/公开来源发现 -> 候选审核 -> 正式资料 -> 确定性提取/显式 AI
  -> 用户确认 -> 搜索/关联 -> 行动专题
```

- 通用资料支持文字、受控图片和单公开 URL；论文、求职与 Debug 是同一资料核心上的领域模板。
- 论文雷达 R1 已完成统一搜索、指定期刊最新浏览、精确核对、多来源有界补全、已见状态、保存规则、
  源码证据、确定性排序和显式候选简报。所有结果继续经过同一候选审核生命周期。
- 工作区切换、清空、删除和版本化完整归档保持隔离；持久运行在启动时恢复为明确终态。
- Windows + WSL 和 Linux 桌面宿主均复用 Vue/FastAPI，并持有自己启动的后端进程组；仍属于
  source-backed 交付，不是已完成纯净机验收的一键发行版。

最近一次 R1 完整门禁（2026-08-30）：后端/桌面 180 项通过，受限沙箱内 1 项 Unix socket skip；
离线 Playwright 17 项通过；`compileall`、Ruff、前端 lint/生产构建和 `git diff --check` 通过。

不要重做现有资料、候选、论文雷达、AI 审计、行动专题、归档或桌面宿主能力。

## 当前收口：R1 一致性

R1 的产品闭环成立，但开始新主线前先修正以下已确认偏差，不增加来源或新能力：

1. 统一 F2 的 UI、API 和文档选择数量上限；当前 UI 为 20，API/旧文档为 50。
2. 工作区切换开始时清除候选排序结果，避免复用候选 ID 时显示旧分数。
3. 工作区切换后的局部请求失败不得保留上一工作区的规则或候选简报。
4. 直接测试 `candidate_ai_runs` 启动中断恢复，并补失败历史与跨工作区简报隔离的离线浏览器断言。
5. 架构中的启动恢复列表与真实 schema v17 生命周期保持一致。

通过既有完整门禁后结束 R1，不借收口扩展论文雷达。

## 下一产品主线：具名 Hexo 博客操作台

ResearchMate 不接管或复制成熟的 `myblog` 工程，而为它提供可选、隔离的受控操作台：

```text
Windows 快捷方式 -> ResearchMate -> /api/blog/*
  -> WSL 中 myblog 的薄机器契约 -> 文章仍由 myblog 独立构建与发布
```

完整边界和验收条件见 [HEXO_BLOG_INTEGRATION_PLAN.md](HEXO_BLOG_INTEGRATION_PLAN.md)。

### B0：myblog 薄机器契约

- 建立从任意目录可调用、固定命令、机器可读 JSON 和统一退出码的接口。
- 首批只覆盖 `check`、元数据 `list`、参数化 `new`、导入 dry-run/apply 和本地 `build`。
- 同名不覆盖；导入计划可复核且原子应用；不 commit、push、deploy 或访问网络。
- 使用临时博客、离线 fixture 和假进程验证，不把文章或 Hexo 规则复制到 ResearchMate。

### B1：ResearchMate 首个纵向切片

- 设置页配置、展示并检查博客路径与公开博客 URL；未配置时不显示入口、不加载博客依赖。
- 博客页列出文章元数据、创建草稿、接收多 Markdown/目录/ZIP，并在再次确认前展示完整导入计划。
- 显示导入与本地构建报告，刷新后仍可见；提供“打开公开博客”，由用户动作访问已发布站点。
- 后端只允许固定操作，UI 不能传入 shell 命令；博客正文、图片与规则仍以 `myblog` 为唯一事实来源。
- 本地 Hexo server 预览和显式 Git 发布均不属于 B1；先验证真实日常工作流是否需要。

B0 与 B1 都必须同时覆盖 UI/API/service/文件边界、失败状态、安全测试和离线 Playwright，不能留下
占位按钮。真实博客写入只在临时副本全部通过后另行明确授权。
