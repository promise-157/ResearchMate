# 当前路线图

本文只保存新会话必须知道的当前事实、有效债务和下一最小切片。详细完成历史见 `CHANGELOG.md` 与

## 已验证基线

ResearchMate 已形成以下本地优先闭环：

```text
导入/公开来源发现 -> 候选审核 -> 正式资料 -> 确定性提取/显式 AI
  -> 用户确认 -> 搜索/关联 -> 行动专题
```

| 范围 | 当前完成事实 |
| --- | --- |
| 通用资料 | 文字、图片和受控单公开 URL；规范化、哈希去重、搜索筛选、状态、标签、来源和工作区隔离 |
| 候选发现 | 受限 arXiv、Crossref IEEE 与单 URL 共用持久任务/候选审核；选定 DOI 用 OpenAlex、严格 arXiv 版本匹配及 DOI 回退保存独立补全事实；接受前不进入正式资料 |
| 图片/OCR | PNG/JPEG/WebP 完整解码和完整性限制；本地 Tesseract；每次明确运行追加审计，接受层独立 |
| 模板 | Debug 与求职的确定性提取、用户确认优先字段和筛选；论文兼容记录幂等映射到通用资料 |
| AI | 通用资料、论文聊天、1–20 篇分析和 2–20 篇综述均使用明确输入范围、结构校验和成功/失败审计 |
| 行动 | 当前工作区 1–20 条有序证据组成行动专题，目标、用户笔记、下一步和状态独立持久化 |
| 稳定性 | 请求固定工作区连接；切换代际隔离；所有持久 `running` 生命周期启动中断恢复 |
| 可移植性 | 一致 SQLite snapshot 加受控图片资产的版本化 ZIP；导入、清空和删除保持工作区隔离 |
| 搜索评估 | 5 万条临时数据下 LIKE 仍满足个人规模；暂不引入 FTS/embedding，触发条件见 `SEARCH_EVALUATION.md` |

不要重做 M11–M16、M6-I1、现有候选浏览器闭环、OCR 重运行、中断恢复或归档能力。详细完成项和
测试演进不再在本文件重复。

## 当前产品主线：论文雷达 R1

### R1-A：Crossref IEEE 正式论文发现（已完成）

目标：不需要 IEEE API Key，通过 Crossref 有界发现正式 IEEE 论文，并进入现有候选审核闭环。

验收摘要：

- 用户确认关键词、期刊或期刊+会议、日期依据与范围、期刊/ISSN、排序和最大数量后才发起请求。
- IEEE 使用 Crossref `10.1109` prefix 与正式文献类型验证；来源侧过滤优先，不无界抓取。
- 每次明确检索新增持久任务；成功、空结果、失败、截断和启动中断均可见。
- 固定 HTTPS endpoint，禁用环境代理/重定向，限制总耗时、分页、记录数和响应大小，使用有界退避。
- 保存 DOI、作者、出版物、类型、多种来源日期、结果位置/分数和 fetched time；缺摘要明确显示。
- 引入最小通用外部身份边界：DOI 强身份优先于正文哈希；标题仅提示可能相同，不自动合并。
- 候选接受前不写正式资料；接受/拒绝、刷新、工作区隔离、清空和完整归档保持现有契约。
- 单元和 Playwright 只使用临时目录、假 transport 和离线 fixture；真实网络只做明确授权的受控验收。
- 上述两个 DOI 必须通过关键词在第一页命中，并验证至少三个不同 IEEE 期刊的近期记录。

预期路径：

```text
LiteratureRadar.vue -> src/frontend/src/api/index.js -> /api/discoveries/crossref
  -> services/discoveries.py -> crawlers/crossref_discovery.py
  -> storage/candidates.py -> workspace SQLite collection_jobs/candidates/items identity
```

R1-A 不实现 OpenAlex 补全、保存订阅、调度、AI 排序、GitHub 检索、PDF、浏览器自动化或通用插件系统。

2026-08-29 离线实现已完成：统一懒加载论文雷达页面同时承载 Crossref 与既有 arXiv 明确检索；
Crossref 使用固定 endpoint、来源侧 IEEE/date/type/ISSN 条件、有界分页/响应/退避，并把空结果、失败、
跳过和截断写入现有任务。schema v13 只增加 nullable `candidates.canonical_id`、任务结果 JSON 和通用
`item_external_identities`；接受按 DOI 身份优先、正文哈希退回，未按标题自动合并。临时 SQLite、假
transport、脱敏 JSON fixture、清空/完整归档和离线 Playwright 已覆盖现有生命周期与工作区隔离。

2026-08-29 受控真实验收已完成：以 `indexed` 日期依据、2026-01-01 至 2026-08-29、期刊类型、相关度
排序和前 10 条上限，两组计划关键词均将目标 DOI 排在第 1 条，并分别覆盖 5 和 7 个不同 IEEE 期刊。
验收无 Key、只读、不写工作区、不访问全文。真实响应暴露并修复了 gzip 流式响应二次解压，以及
“8 月索引、10 月正式出版”不能共用含糊日期范围的问题；必要形状已脱敏为离线 fixture。

R1-B 第一小切片已完成：页面按主题搜索、指定期刊最新、标题/DOI 精确查找三种用户意图切换字段并

### R1-C：多来源有界补全与版本关系（已完成）

统一论文雷达只对用户明确选择并确认的 1–20 条当前 Crossref DOI 候选发出一次有界 OpenAlex 请求。
schema v14 的 `candidate_source_records` 保存逐候选成功或失败，不覆盖 Crossref、审核状态或正式资料；
任务显示部分成功，页面显示摘要、机构、主题、引用和开放版本证据，并明确正式记录、预印本、开放版本
以及 online/print/indexed 日期的差异。OpenAlex 缺摘要时，先以严格标题加作者证据匹配 arXiv 版本，
再对仍缺失者按 DOI 批量查询 Semantic Scholar；各来源可独立失败，`CLOSED` 不冒充开放全文。无摘要
样本保持缺失。清空、完整归档、恢复、离线单元与浏览器
边界已覆盖，未加入自动补全、队列、第二套缓存、AI、GitHub、PDF 或插件系统。

2026-08-30 扩大受控真实验收：3 个主题的 Crossref 有界查询返回 60 条，从中选择 2026 年 7–8 月、
15 本不同 IEEE 期刊的 15 个 DOI；OpenAlex 命中 14 条并提供 10 篇摘要，Semantic Scholar 对 5 个缺口
全部返回精确 DOI 记录并补齐 4 篇，最终摘要覆盖 14/15。唯一缺失是栏目性内容 `Global Communications
Newsletter`，说明正式 `journal-article` 类型仍可能混入非研究内容，后续检索质量不能仅靠摘要补全解决。
该验收无 Key、只读、不写工作区，未访问 IEEE Xplore 页面、PDF 或全文；样本结果不是全量覆盖承诺。

### R1-F1：少量候选源码证据（已完成）

用户已明确要求在稳定的多来源候选上核对开源仓库，并用多样化近期真实论文验收。本切片只完成源码
证据，不捆绑 R1-F 的排序或 AI，也不提前实现 R1-D/R1-E：

- 用户明确选择并确认当前工作区 1–5 条待审核论文；页面复述标题、DOI/arXiv ID 和外发范围。
- 优先采用论文/arXiv 元数据明确声明的 GitHub 仓库；否则每篇最多一次 GitHub repository search，
  最多核验前三个公开 README。无 Key、禁用代理/重定向并有总时长、响应大小和请求数上限。
- 明确来源链接标为“论文声明”；README 同一 DOI/arXiv ID 标为强关联；完整标题只标为实现候选，
  不能自动称官方。未找到只表示本次有界检查没有证据。
- 保存规范仓库 URL、证据等级、命中字段、公开仓库状态/许可证和独立成功或失败；不保存 README，
  不克隆仓库、不下载代码或 release，不覆盖论文来源事实、审核状态或正式资料。
- 单篇或 GitHub 来源失败不制造结果且不抹掉其他候选；统一雷达展示可安全打开的仓库和证据解释。
  刷新、工作区隔离、清空和完整归档复用现有 `candidate_source_records` 边界。
- 单元测试只用临时 SQLite、假 transport 和离线 fixture；离线门禁通过后，以无 Key、只读请求验收
  多篇近期且已知有官方/机构/第三方仓库的论文，同时包含未发现和失败形状。

2026-08-30 真实验收使用 5 篇不同形状的 2026 IEEE 记录：TIFS 论文声明且仓库可访问；ISQED 论文
声明的仓库当前 404；ICASSP CONQUER 由 README 同一 DOI 强关联；RA-L MIGHTY 由 DOI 和 arXiv ID
双强身份关联且取得 BSD-3-Clause；Communications Magazine 栏目内容未发现源码且未误报。真实数据
暴露并修复了长标题零召回、同名缩写噪声、搜索 JSON 大小和失效声明仓库语义。所有请求无 Key、
只读，未克隆仓库、下载代码或写工作区。

### R1-D：已见管理与上下文探索（已完成）

- 新 Crossref/arXiv 强身份候选保存上次候选 ID、终态、时间和关联资料，只追加本次候选而不改历史。
- 统一雷达明确区分新发现、以前见过、以前拒绝和已入库；默认隐藏旧结果并显示数量，可恢复查看。
- 已入库重复项仍可核对且接受时复用唯一资料；拒绝历史不阻止本次重新审核。
- 候选可填充“同一期刊、同一作者、按标题继续搜、核对版本”的明确条件，但不得自动联网。
  作者搜索使用 Crossref `query.author`，不伪装为主题搜索。
- 不新增表、订阅、调度、推荐算法或队列；刷新、工作区隔离、清空和归档复用既有边界。

新 Crossref 与 arXiv 强身份候选现携带最近候选状态和唯一资料归属；雷达默认隐藏旧结果、显示隐藏数量，
可恢复并区分以前见过、以前拒绝和已入库。重复接受继续复用唯一资料。候选可填充同一期刊、首位作者、
完整标题和版本核对条件；作者意图明确映射 Crossref `query.author`，所有上下文动作都不会自动联网。

### R1-E：保存规则与增量运行（已完成）

schema v16 的工作区级 `saved_discovery_rules` 支持命名保存、真正更新、载入、删除、单条运行和明确确认的
串行“运行全部”。首次运行使用用户保存的有界范围；成功后记录任务检查点，随后非精确搜索从最后成功
时间前 2 天重叠检查至当天。失败状态和错误可见且不推进成功检查点；每次仍创建普通任务和候选，DOI
强身份继续区分新增与已见。规则及检查点随工作区清空和完整归档迁移，局部接口失败不会遮蔽已加载候选。

2026-08-30 无 Key、只读、不写工作区的真实 Crossref 验收，以 IEEE Access 索引日期运行一次 30 天窗口
和一次 2 天重叠窗口，各返回上限内 20 条；重叠窗口 20 个 DOI 均被首次集合识别为已见。样本也证明
“新进入索引”可能是旧年份论文，不能混写成最新发表。当前没有用户需要应用关闭后自动执行的证据，
因此调度评估结论为不加入常驻调度器、队列或后台进程；手动批量即本阶段完成边界。
