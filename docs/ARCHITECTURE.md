# ResearchMate 架构

## 系统边界

```text
Vue UI -> /api -> application service -> repository -> workspace SQLite
                             |-> collector -> public API/feed/page
                             `-> processor -> local rules/OCR/AI provider
```

浏览器不直接访问来源或 AI 服务。后端统一负责凭证、输入边界、超时、限速、规范化、审计和错误处理。

## 核心模型

- `items`：规范化资料项和用户工作流状态。
- `assets`：仅保存用户主动导入的本地文件及其哈希；远程附件默认不下载。
- `extraction_runs`：本地/AI 提取的版本化运行记录。
- `accepted_extractions`：用户从成功的确定性运行中明确采用的当前文本值，保留运行引用；不改写 `items.content_text` 或运行历史。
- `item_relations`：重复、相似、引用和用户关联。
- `item_template_data`：领域模板的 schema 版本、确定性提取值和用户确认值；确认值独立保存并覆盖展示，不覆盖提取事实。
- `collection_jobs`：搜索、同步和候选采集任务。
- `candidates`：采集结果的审核缓冲区；只有显式接受才关联或创建 `items`。
- `papers` 等旧表：迁移期兼容数据；`papers.item_id` 将论文专用记录映射到通用核心，专用视图继续读取兼容字段。

通用字段使用正式列；领域扩展字段使用有 schema 版本的 JSON。高频查询字段在模板稳定后提升为正式列或索引，避免无边界 EAV，也避免为每个场景复制表。

当前第一个模板是 `debug` schema v1。标签规则只读取本地正文，提取错误、环境、尝试、根因和方案；每次重新提取写审计运行并只替换 `extracted_json`，`confirmed_json` 只能由用户动作修改。近似文本使用本地 `token-jaccard-v1`，结果和共同 token 证据写入 `item_relations`；它不是语义向量检索。

## 数据不变量

- `content_hash` 基于规范化可分析文本，用于同一工作区的精确去重。
- 来源事实不可由 AI 覆盖。
- AI 输出只写运行记录和建议字段；用户确认值优先。
- 接受确定性提取必须是显式用户动作；搜索与 AI 默认不扩大到接受层，只有请求范围明确选择时才读取。
- 每个外部结果必须保留来源类型、URL/标识符和采集时间。
- 数据库变化通过幂等迁移完成，现有工作区可原地升级。
- 清空工作区等破坏性动作必须明确包含通用资料和兼容数据的范围。
- 图片资产使用数据库中的受控相对路径映射到 `src/data/assets/` 的工作区隔离目录；API 不接受客户端提供的文件路径。

## 采集器契约

采集器输出最小规范化候选，不直接决定是否正式入库。每个网络采集器必须具名、匹配明确来源、使用公开允许的入口、限制数量/超时/频率、提供 fixture 测试并返回可见错误。

遗留通用 HTML 采集器继续默认关闭。URL 导入是单个用户指定页面的受控读取，不等于站点爬取。

`single_public_url` 只接受标准端口上的公开 HTTP/HTTPS 页面。每次请求和重定向都校验 DNS，连接后复核对端地址，禁用环境代理，检查每个来源的 robots 策略，并限制总耗时、重定向次数、解压后响应大小和内容类型。结果先写入 `candidates`，接受动作才通过通用资料服务入库或关联已有指纹。

`arxiv_api` 是首个多结果发现适配器。只有用户明确提交搜索词时才向 arXiv 官方公开 API 发出一次受限请求；单次 1–20 条、总耗时 25 秒、响应上限 2 MB，不下载 PDF。一个 `collection_jobs` 可关联多条 `candidates`，任务状态、查询、数量和错误持久化；搜索结果仍须逐条接受或拒绝。

论文兼容迁移只为缺少映射的记录创建或关联资料。指纹命中已有资料时不得覆盖其用户字段；来源刷新继续更新 `papers` 中的来源事实，不静默重写已映射资料。

## 处理器契约

处理器接收明确版本的输入并返回结构化结果：

- 确定性处理器：规范化、哈希、规则分类、OCR、字段验证。
- AI 处理器：分类、字段建议、摘要、比较和综合分析。

处理失败不得制造结果。真实网络和真实 AI 不进入自动测试。

当前 M8 只允许把成功的本地 OCR 文本接受到通用接受层。接受动作校验资料归属、运行状态、`provider=local` 和受支持的运行类型；同一资料同一提取类型只保留一个当前采用版本，旧运行继续留在 `extraction_runs`。Debug 模板仍使用自己的确定性提取/用户确认分层，不通过这一入口提前抽象。

## 完成定义

一个用户功能只有在 UI、API、服务、存储、失败状态、测试和文档一致时才算完成。后台任务必须有可查询状态；“已启动”不能显示成“已完成”。
