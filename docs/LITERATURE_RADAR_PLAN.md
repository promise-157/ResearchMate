# 论文雷达 R1 计划

本文是 ResearchMate 从“用户已经有资料时帮助整理”走向“高效率查找、核对和持续发现论文”的新产品起点。
它使用独立的 `R1` 阶段编号，不延续旧里程碑数字。旧里程碑的完成事实仍在
[ROADMAP.md](ROADMAP.md) 和 `CHANGELOG.md`；仍有效债务列在本文末尾，不会被新主线掩盖。

## 要解决的问题

用户需要的不是另一个返回成百上千条链接的搜索框，也不是只能订阅固定研究方向的更新器，而是一个
可信的统一论文搜索工作台：

- 高效完成临时主题搜索、指定期刊最新浏览、作者检索、标题/DOI 精确查找和正式版本核对；
- 支持单次探索，也允许把确实需要重复运行的有效条件保存为持续关注；
- 优先发现最新、正式发表在 IEEE 及其他期刊/会议的论文，并允许从期刊、论文或作者继续探索；
- 区分预印本首次公开、在线发表、正式卷期和索引更新时间；
- 在大量结果中先做来源侧过滤、本地去重和可解释排序，只把少量候选交给用户；
- 尽可能找到论文对应的公开版本和源码仓库，并展示判断证据而非猜测；
- 所有网络请求由用户明确触发并形成持久任务，候选经用户接受后才进入正式资料库；
- 未来支持保存的检索规则和增量检查，但不把不透明的常驻爬虫作为第一步。

R1 的价值不在于比单个开源项目支持更多网站，而在于让用户更快表达搜索意图、更快判断结果，再把
正式发表事实、多来源补全、候选审核、源码证据、工作区隔离、审计历史和后续资料/AI/行动流程连接
成一个本地优先闭环。来源是后台策略，不是要求用户理解的页面结构。

## 搜索体验原则

- **先表达意图**：主题搜索、指定期刊最新、作者、标题/DOI 精确查找和版本核对是用户入口；来源参数
  是实现细节。第一切片只提供已验证的关键词与期刊范围，不伪装尚未支持的意图。
- **提交前可确认**：用自然语言复述关键词、期刊/会议、日期、排序和上限；网络请求只能由用户明确提交。
- **修改条件要便宜**：常用日期范围、最近条件、期刊名与 ISSN 联动、高级条件收起和可删除筛选标签
  应逐步减少重复输入，不能要求用户记住来源语法。
- **判断结果要快**：突出正式状态、关键日期、期刊、匹配原因、摘要缺失、已见/已拒绝/已入库和来源
  不完整性；相同 DOI 自动关联，标题相似只提示核对。
- **失败不等于空结果**：空结果、条件过严、来源失败、部分结果和截断必须区分，并给出可执行的调整建议。
- **探索不强迫订阅**：临时搜索可以直接结束；从论文继续查作者、期刊或正式版本属于上下文动作，只有
  用户确认会重复使用时才保存规则。

## 防止成为缝合怪的架构预算

R1 不是一次性把所有阶段都实现。每个切片必须满足以下预算，超出时先停下来说明真实原因：

- **一个候选生命周期**：所有来源继续使用 `collection_jobs -> candidates -> 用户审核 -> items`，
  不为 Crossref、OpenAlex 或 GitHub 各造任务表、候选箱和接受流程。
- **一个薄适配器接口**：适配器只负责受限 I/O 与来源响应解析，查询编排属于 service，SQL 属于
  repository。R1-A 只有一个 Crossref 适配器，不预建二十种来源的通用框架。
- **一个规范论文身份规则**：DOI 是正式论文首要身份，arXiv ID 是预印本身份，标题只能产生
  “可能相同”关系。正文哈希继续判断内容重复，不能代替 DOI。
- **一个统一页面**：论文雷达按来源和规则过滤，不按来源增加页面。该路由继续懒加载，不能扩大首屏
  bundle；资料中心只保留候选审核或通往雷达的清晰入口，不复制完整搜索表单。
- **零新增基础设施**：R1-A 不增加 MongoDB、Redis、Celery、浏览器运行时、向量库、MCP 服务、
  独立 CLI 或第二套 SQLite 缓存；使用现有 FastAPI、httpx、Vue 和工作区 SQLite。
- **零来源专属依赖**：能用现有标准库/httpx 安全实现时不增加 pip/npm 包。HTML entity、日期和 DOI
  规范化使用小型纯函数并有 fixture 测试。
- **无静默降级**：来源失败、结果截断、字段缺失、跳过记录和部分补全都可见；“没有结果”、
  “没有摘要”和“请求失败”是三个不同状态。
- **阶段门禁**：R1-B 至 R1-F 是有进入条件的后续切片，不是 R1-A 的待办清单。没有真实使用证据时
  不提前实现调度、AI、GitHub、全文或通用插件系统。

代码评审时若一个来源需要修改路由、service、存储和 UI 中大量 `if source == ...`，视为边界设计
失败；但只有一个实现时也不为猜想中的未来来源抽象。第二个真实补全来源出现时才提取共享协议。

相同 Crossref 查询还返回 IEEE Transactions on Robotics、Vehicular Technology、Industrial
Electronics、Instrumentation and Measurement、Communications、Automation Science and Engineering、
Internet of Things Journal、Sensors Journal、J-STARS 等不同出版物的 2026 年记录。这证明首个切片

验证同时暴露了必须正视的缺口：Crossref 的 IEEE 记录通常没有摘要；OpenAlex 对第一篇有摘要、

来源都不能充当全部事实，缺失字段必须明确显示为缺失。

## 来源策略

### R1 必需来源

1. **Crossref 正式发表发现**：以 DOI、类型、期刊/会议、作者、正式日期和元数据更新时间为主。
   IEEE 初始范围使用 `10.1109` DOI prefix，并允许按期刊名或 ISSN 继续缩小。
2. **OpenAlex 元数据补全**：以 DOI 精确关联摘要、机构、主题、引用、开放版本、来源和出版方层级。
   OpenAlex 值保留自身 provenance，不能覆盖 Crossref 的原始来源事实。

### 后续可选来源

- Semantic Scholar：补充摘要、引用、相似论文和预印本映射；限流或缺失不能使主任务失败。
- DBLP：补充计算机领域的正式出版记录；没有摘要时保持缺失。
- arXiv：作为预印本/开放版本来源，继续复用现有受限适配器，不把预印本伪装成正式发表。
- GitHub：只对用户选择或本地排序后的少量候选查找源码线索，绝不对全量结果逐篇搜索。
- IEEE/出版商页面：只保留 DOI 跳转；浏览器辅助只有在真实覆盖评估证明必要后才另行设计。

不直接复制无许可证爬虫源码。可以阅读和验证 `paperCrawler` 等项目的行为并独立实现同类能力；
直接抓出版商 HTML 不是 R1 的可靠性基础，也不得绕过登录、付费墙、CAPTCHA、robots 或限流。

## 用户工作流

```text
选择搜索意图并填写条件
  -> 页面复述确切范围，用户明确提交
  -> 后端选择具名来源并尽量在来源侧限定范围
  -> 持久化本次成功或失败任务
  -> 强身份去重、已见识别和来源事实整理
  -> 生成待审核候选，不自动入库
  -> 必要时对明确的小范围做多来源补全
  -> 用户接受、拒绝或稍后处理
  -> 可从结果继续查期刊、作者、版本或相近主题
  -> 确有重复价值时保存为增量规则
  -> 只有接受后进入正式资料及既有分析/行动流程
```

论文雷达是一个统一页面；Crossref、OpenAlex、arXiv 等是来源筛选器，不为每个来源新增顶级页面。
第一切片只支持用户点击“立即检索”，不引入常驻调度器。保存规则和增量检查建立在手动流程稳定后。

## 数据与不变量

### 来源事实分层

每个候选必须保留来源级事实，至少包括：

- `source_record_id`、`source_url`、`fetched_at`；
- 规范化 DOI、标题、作者、出版物、文献类型；
- 来源声明的 online/print/issued/created/indexed/updated 日期；
- 原始来源是否声明正式版本、开放版本和摘要；
- 查询条件、结果位置和可用相关度分数。

聚合展示可以选择更完整字段，但必须能回答“这个字段来自哪里”。Crossref、OpenAlex、Semantic
Scholar 和用户确认值互不覆盖。预印本与正式论文可以建立关系，但保持各自标识和日期。

### 去重与候选历史

- DOI 规范化为小写、移除 `https://doi.org/` 前缀后作为首要身份；大小写差异不是新论文。
- DOI 缺失时使用规范化标题指纹作为候选关系提示，不自动断言相同论文。
- 同一次任务的重复来源结果聚合为一个展示候选和多份来源证据。
- 不同任务发现同一 DOI 时保留任务历史，并关联已有候选/资料；不能静默制造重复正式资料。
- 接受或拒绝是用户动作；来源刷新不得覆盖正式资料的用户字段、笔记、状态或确认层。

R1-A 需要补上现有“只按正文哈希接受”的身份缺口，但保持最小：候选增加可索引的 nullable
`canonical_id`（首版形如 `doi:10.1109/...`）；正式资料使用通用的外部身份映射保存类型和值。
接受时先查规范身份、再查正文哈希。这样相同 DOI 的摘要完整度变化不会制造两篇资料，也不要求给
`items` 增加 IEEE 专属列。标题指纹不进入唯一约束。R1-B 出现一个候选对应多份来源记录时，再依据
真实响应决定是否增加来源证据子表；R1-A 不预建。

### 源码证据

源码发现使用以下有序证据等级：

1. 论文元数据、摘要、作者项目页明确给出仓库；
2. 仓库 README 包含完全一致 DOI；
3. 仓库 README 包含完整标题并匹配作者；
4. 仅标题/作者/算法名的模糊候选；
5. 用户明确确认。

前四层是机器发现事实，第五层是独立用户确认。模糊候选不能显示为“已有官方源码”。每次检查保存
查询范围、时间、结果和失败；缓存避免重复请求，但用户明确重新检查会创建新运行。

## 交付阶段

### R1-A：Crossref IEEE 正式论文发现（已完成）

目标：不用 IEEE Key，通过真实关键词稳定发现正式 IEEE 候选，并进入现有审核闭环。

验收条件：

- UI 统一显示“论文雷达”入口，提交前明确展示关键词、文献类型、日期依据与范围、期刊/ISSN、排序和
  本次最大返回数；最大返回数有服务端上限，不允许无界全量抓取。
- 首版支持 `IEEE 期刊` 和 `IEEE 期刊 + 会议`，默认只查期刊；IEEE 事实由 Crossref
  `10.1109` prefix 加文献类型验证，不用标题猜出版方。
- 每次点击创建新的持久 `collection_jobs`，成功、空结果、超时、HTTP/格式/大小错误均保留；启动
  中断恢复沿用现有契约，不静默复用旧任务。
- collector 固定 HTTPS endpoint，禁用环境代理和重定向，限制总耗时、页数、每页/总记录数及响应
  解压后大小；遵守 `Retry-After` 和有界退避，不使用真实 Key。联系邮箱只是未来可选的 polite-pool
  配置，不得用虚构邮箱，也不能成为首次使用前置。
- 解析并保留 DOI、标题、作者、期刊/会议、类型、正式日期、created/indexed、结果名次、分数和
  fetched time；HTML entity 正常解码，缺失摘要明确显示。
- 日期范围必须明确选择正式发表日期或 Crossref 索引日期；“最新进入索引”不能被误写成“最新正式发表”。
- DOI 去重；本次重复不能产生多个候选。跨任务命中已有候选/资料时显示关系，不覆盖原记录。
- schema 只增加通用规范身份所需的最小迁移；现有 URL/arXiv 候选和没有身份的资料保持兼容，迁移
  幂等且不根据模糊标题回填身份。
- 候选接受/拒绝继续复用现有 service 边界，接受前不写正式资料；接受后 DOI provenance 不丢失。
- UI 展示本次任务、来源、条件、成功/失败、结果数以及候选的正式发表证据；刷新和工作区切换不丢失、
  不串库。
- 清空工作区和完整 ZIP 归档往返包含新任务/候选事实；不包含全局邮箱、Key 或网络缓存。
- 临时 SQLite、假 transport 和离线 fixture 覆盖 API/UI 成功、空结果、分页、重复、格式错误、限流、
  刷新、隔离、中断、清空和归档；普通测试不访问网络。
- 经用户明确授权的受控真实验收中，以下查询在第一页返回对应 DOI：
  - `Hermite spline trajectory planning` -> `10.1109/LRA.2026.3681187`
  - `simultaneous localization 3D semi dense mapping micro drones monocular inertial`
    -> `10.1109/LRA.2026.3713731`
- 同次真实验收另确认至少三个不同 IEEE 期刊存在近期记录；真实响应形状转成脱敏离线 fixture。

预期实现路径：

```text
LiteratureRadar.vue -> src/frontend/src/api/index.js -> /api/discoveries/crossref
  -> services/discoveries.py -> crawlers/crossref_discovery.py
  -> storage/candidates.py -> workspace SQLite collection_jobs/candidates
```

R1-A 不实现保存订阅、定时任务、AI 排序、GitHub 搜索、全文下载或浏览器自动化。

2026-08-29 R1-A 已完成受控真实验收。按 `indexed` 日期依据、2026-01-01 至 2026-08-29、期刊类型、
相关度排序和前 10 条上限，两组计划关键词均把目标 DOI 排在第 1 条，结果分别覆盖 5 和 7 个不同 IEEE
期刊。验收同时发现第二篇在 2026-08-19 已被索引但正式 `published` 日期为 2026-10，因此实现新增了
明确的“索引日期/正式发表日期”选择，不能把二者混写成“最新”。真实 gzip 响应还暴露并修复了流式
解压后二次解压问题；两种真实响应形状均已脱敏为离线 fixture。请求无 Key、只读、不写工作区、不访问
全文。R1-A 门禁通过，下一切片是搜索意图与期刊体验 R1-B，而不是直接做 OpenAlex 或保存订阅。

### R1-B：高效率搜索意图与期刊体验（已完成）

进入条件：R1-A 的任务、去重和候选审核在离线及受控真实验收中稳定。

- 以用户意图组织主题、指定期刊最新、标题/DOI 精确查找；作者检索只在来源契约验证后加入。
- 期刊名与 ISSN 形成可搜索、可确认的选择体验，不要求用户记住 ISSN；先证明单期刊，再评估少量多期刊。
- 提供最近 7/30 天、今年和自定义日期等快捷范围，自然语言复述最终条件，高级条件默认不妨碍简单搜索。
- 空结果给出放宽日期、期刊或关键词的建议；截断显示数量和继续方式；修改条件保留当前上下文。
- 临时搜索不要求保存规则；不得为了通用查询语言提前建设复杂 DSL 或期刊镜像数据库。

首个纵向切片完成了：统一页面先让用户选择主题搜索、指定期刊最新或标题/DOI 精确查找，只显示当前
意图需要的条件并复述最终请求；主题使用有界 bibliographic 查询，期刊最新允许无关键词但强制期刊名
或 ISSN，精确 DOI 只请求一个规范身份记录，精确标题使用标题查询。三者共享同一任务、候选、审核和
归档边界。

第二个纵向切片完成了：页面提供明确标注为非完整目录的常用 IEEE 期刊快捷项，选择后联动规范名称与
ISSN，同时保留自定义输入；最近 7 天、30 天和今年快捷项只修改表单；持久任务可重新载入修改；空结果
按主题、期刊最新和精确查找给出不同的可执行建议，扩大日期、移除期刊或切换索引日期都不会自动重试。
离线浏览器断言这些辅助动作不增加请求。R1-B 完成，不以静态快捷项冒充完整期刊目录。

### R1-C：多来源补全与版本关系（已完成）

进入条件：R1-B 已证明用户能稳定得到范围正确、数量可控的候选。

- 用户明确选择为本次少量候选补全，或在检索确认中预先看到精确 DOI 数量。
- OpenAlex 按 DOI 补充摘要、机构、主题、引用和开放版本；缺摘要时以标题完全相同且共享完整作者的证据
  关联 arXiv 版本，仍缺失才按 DOI 查询 Semantic Scholar；来源事实互不覆盖，后两者可独立失败。
- 聚合视图解释 online/print/indexed 日期差异以及预印本、正式版本和开放版本关系。
- 第二篇验收样本必须保留“正式论文存在但 OpenAlex 无摘要”，并把后续找到的预印本摘要明确标为
  arXiv 版本事实；不得把它伪装成正式出版方摘要，也不得因某一回退失败而整批失败。

2026-08-30 完成最小纵向切片：统一论文雷达允许用户勾选并确认 1–20 条当前 Crossref DOI 候选，使用
一次固定 endpoint 的 OpenAlex 批量请求补全；每个候选把成功事实或缺失错误保存在通用
`candidate_source_records`，任务汇总显示成功、失败和部分成功。展示保留来源标签，并分别说明
Crossref 正式记录、arXiv 预印本和 OpenAlex 开放版本线索；online、print、indexed 日期不混写。
离线样本覆盖一篇有摘要/机构/主题/开放版本的记录，以及一篇正式记录存在但 OpenAlex 无摘要的记录；
后者仅在严格标题和作者证据成立时显示独立 arXiv 版本摘要，仍缺失才使用 DOI 精确回退，绝不制造
正式出版方摘要。清空、完整归档、刷新、工作区隔离和启动中断恢复沿用现有边界。
本阶段没有加入自动全量补全、第二套缓存、队列、AI、GitHub、PDF、浏览器自动化或插件系统。

同日扩大受控真实验收以 3 个主题取得 60 条 Crossref 结果，从中选择 15 本不同 IEEE 期刊、覆盖
2026 年 7–8 月的 15 个 DOI。OpenAlex 命中 14 条并提供 10 篇摘要；对 5 个缺口，Semantic Scholar
均返回精确 DOI 记录并补齐 4 篇，最终 14/15 有摘要。唯一缺失的 `Global Communications Newsletter`
是栏目性内容，暴露出 Crossref `journal-article` 仍可能包含非研究材料，不能靠制造摘要解决。真实验收
无 Key、只读、不写工作区，未访问 IEEE Xplore 页面、PDF 或全文；结果只说明本次样本，不承诺全覆盖。

### R1-D：已见管理与上下文探索（已完成）

进入条件：真实搜索开始产生跨任务重复结果，且用户需要从结果继续探索。

- 结果明确区分新发现、以前见过、已拒绝和已入库；默认弱化旧结果但允许恢复查看。
- 从论文一键继续查看同一期刊最新、按作者检索、精确标题/DOI 核对或带入相近主题，提交前仍确认范围。
- DOI/arXiv 强身份自动关联；标题相似只展示证据并交给用户判断。

实现结果：新候选保存最近同身份候选的状态、时间与资料归属；页面默认隐藏旧结果且允许恢复，区分
以前见过、以前拒绝和已入库。上下文动作只填充同一期刊、Crossref 作者、标题主题或版本核对条件，
不自动联网。既有历史候选不被重写，重复接受仍复用唯一资料。
- 支持在已取得结果内快速二次筛选，避免每次修改展示条件都重新访问来源。

### R1-E：保存规则与增量运行

进入条件：用户实际重复运行相同搜索，证明保存规则能减少负担。

- 保存意图、关键词、排除词、期刊/ISSN、类型、日期策略和上限，不保存 Key。
- 首次回溯有界；后续按最后成功检查点加重叠窗口，并用强身份区分新增和已见。
- 先实现手动“运行全部已保存规则”，再依据真实需求决定本机调度；失败不能错误推进检查点。

R1-E 已完成：工作区级 Crossref 规则可保存、更新、载入、删除、单条运行和明确确认后串行运行全部；
首次使用保存范围，成功后以最后成功时间前 2 天作为重叠窗口，失败只更新可见终态而不推进检查点。
每次运行继续复用原任务/候选及 DOI 已见识别，清空和完整归档包含规则与检查点。真实 IEEE Access
重复窗口验证了强身份已见行为，也显示索引更新可能对应旧论文。当前没有应用关闭后自动运行的真实需求
证据，因此本阶段明确不增加调度器、后台队列或常驻进程。

### R1-F：源码证据、可解释排序与小范围简报

进入条件：多来源候选已经稳定，且真实候选量证明仍需进一步降低判断成本。

- 只对用户选择的少量候选检查源码；DOI、完整标题和作者匹配分级展示，未找到只表示本次未发现。
- 先用关键词命中、日期、期刊、已见状态、摘要和源码证据做确定性排序并解释分数。
- AI 只作用于用户明确的小范围并创建独立审计，不能修改来源事实或自动接受资料。

R1-F 已完成：F1 每次明确选择 1–5 篇并保存分级源码证据；F2 对选择的候选做不联网、不删结果的本地
解释排序，逐项显示关键词/标题、日期、期刊、已见、摘要和源码分值；F3 只在用户确认 2–10 条范围后，
把有界元数据和评分理由交给已配置模型，并建立独立成功/失败审计。真实十条 Crossref 样本促使标题
全词命中权重高于日期，并将已知 MIGHTY DOI 排到第 1。F3 仅以假 provider 离线验收，未使用真实
AI/Key；推断不覆盖来源事实、分数或审核状态，也不自动入库。

## 开源项目取舍

| 项目 | 可吸收能力 | 集成决定 |
| --- | --- | --- |
| `paperCrawler` | 期刊监视、布尔过滤、DBLP/公开索引补全、已见去重 | 阅读与行为对照；无明确许可证时不复制源码，不作为必需运行时 |
| `findpapers` | 多源查询表达式、DOI 合并、元数据 enrichment | 参考数据归一化；ResearchMate 自行实现薄适配器，避免第二套审计/缓存 |
| `MOSAIC` | 来源注册、JSON 输出、SQLite 缓存、可选依赖 | 参考来源边界与降级策略；不捆绑整套 CLI/Web UI |
| `easyScholar` | 浏览器内期刊等级展示 | 可作为将来用户浏览辅助参考，不承担后台发现 |
| `papers` | OpenAlex publisher/source 过滤、Zotero 衔接 | 参考查询体验；不引入 Rust 服务、向量库或第二套资料库 |

源码审查得到的明确取舍：

- 不采用“最长字符串/最大数字就是最佳值”的通用合并；每个聚合字段保留选值规则和来源。
- 不采用标题相同即自动合并；DOI/arXiv 等强身份才能自动合并，标题只提示人工核对。
- 尽量把日期、类型、出版方和期刊过滤发送到来源端；先取固定前 N 条再本地过滤会造成静默漏检。
- 排序默认不删除结果；如果以后增加阈值过滤，必须显示过滤前后数量和原因。
- 不把摘要中出现的第一个 URL 当成源码；只识别允许的仓库 host，并保存 DOI/标题/作者匹配证据。
- 不用并发 fan-out 掩盖来源错误。多来源出现后，每个来源有独立终态，聚合任务才能声明部分成功。

只有当第三方库具有明确兼容许可证、稳定机器接口、独立维护价值并且不会复制 ResearchMate 的存储与
审计职责时，才考虑作为依赖。否则优先实现小型来源适配器。

## 明确不做

- 不批量下载 IEEE 或其他出版商 PDF，不镜像网站。
- 不模拟登录、破解验证码、绕过订阅、robots、访问控制或限流。
- 不把“能打开 DOI”误写成“有全文访问权”。
- 不对上千篇候选逐篇调用 AI 或 GitHub。
- 不在第一阶段建设通用插件系统、常驻爬虫集群、向量数据库或第二套论文管理器。
- 不把论文雷达拆成每个来源一个顶级页面。

## R1 完成标准

R1 只有在用户无需理解各来源参数，就能高效完成临时主题搜索、指定期刊最新浏览、精确论文核对和
真实需要的持续关注；能快速修改范围、理解空结果/截断/失败、识别已见与版本关系、追溯字段来源，
并把选中的候选无损送入既有资料/分析/行动闭环时才完成。支持若干 API、返回大量结果或只能保存固定
方向订阅都不构成完成。
