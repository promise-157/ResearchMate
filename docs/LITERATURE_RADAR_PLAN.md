# 论文雷达 R1 完成记录

R1 已于 2026-08-30 完成。本文保存仍然有效的产品边界、实现不变量、真实验收结论和已知限制；逐阶段
开发过程与详细改动见 [CHANGELOG.md](../CHANGELOG.md) 和 Git 历史，不再作为当前路线图重复维护。

## 用户效果

论文雷达不是固定研究方向的订阅器，也不是简单的论文搜索框。用户可以在同一页面完成：

- 临时主题搜索、指定期刊最新浏览、标题或 DOI 精确核对；
- 明确日期依据、期刊/ISSN、排序和数量后再发送请求；
- 对候选补全摘要、机构、主题、开放版本和预印本关系；
- 区分新发现、以前见过、以前拒绝和已经入库；
- 保存真正有用的搜索规则，并手动执行带重叠窗口的增量检查；
- 对少量候选核对源码证据、运行可解释本地排序，并在明确范围内请求 AI 简报；
- 最终逐篇接受或拒绝，避免搜索噪声直接污染正式资料库。

## 架构与数据不变量

所有来源共用一个生命周期：

```text
LiteratureRadar.vue -> /api/discoveries/* -> services/discoveries.py
  -> named collector/enrichment -> collection_jobs/candidates
  -> accept_candidate -> items + item_external_identities
```

- arXiv 和 Crossref 是具名发现来源；OpenAlex、严格 arXiv 版本匹配、Semantic Scholar 与 GitHub
  只对用户明确选择的候选做有界补全，不建设第二套候选缓存或通用插件系统。
- 接受前不写正式资料。DOI/arXiv 强身份优先于正文哈希；标题只提示可能相同，不自动合并。
- Crossref 原始事实、多来源补全、确定性分数、AI 推断和用户审核相互独立，后续处理不覆盖来源事实。
- 候选、任务、保存规则、来源记录与 AI 简报均受工作区清空、完整归档、启动恢复和隔离约束。
- 不默认下载 PDF、克隆源码、保存 README、抓取 IEEE Xplore 页面或绕过访问控制。
- 普通测试只使用临时目录、假 transport/provider 和离线 fixture；真实来源验收必须另行授权且只读。

## 来源策略与解释

- Crossref 用于正式 DOI 发现，IEEE 通过 `10.1109` prefix、正式文献类型及可选期刊/ISSN 验证；
  `published` 与 `indexed` 日期必须分别解释。
- OpenAlex 批量补充摘要、机构、主题、引用和开放版本线索；开放页面不能冒充正式出版页。
- OpenAlex 缺摘要时，只有规范化标题完全相同且共享完整作者才关联 arXiv；仍缺失时才按精确 DOI
  请求 Semantic Scholar。任何来源失败都不能抹掉其他来源事实。
- GitHub 优先核验论文明确声明的仓库，否则每篇只做一次有界搜索并检查少量 README。DOI/arXiv ID
  是强证据；完整标题和作者只能称实现候选；未找到只代表本次检查没有证据。
- 本地排序中标题关注词优先于日期，期刊、新旧状态、摘要和源码只作可见加分；排序不删除候选。

## 真实验收结论

2026-08-29 至 2026-08-30 的受控验收均无 Key、只读、不写工作区：

- 两组计划关键词均在 Crossref IEEE 前十结果中把目标 DOI 排在第 1，并覆盖多个 IEEE 期刊。
- 15 个 2026 年 7–8 月、来自 15 本不同 IEEE 期刊的 DOI 中，OpenAlex 命中 14 条；结合 Semantic
  Scholar 后取得 14 篇摘要。唯一缺失是栏目性内容，证明 `journal-article` 仍不等于研究论文。
- 五篇不同形状论文的源码验收覆盖可访问声明仓库、失效声明仓库、README DOI 强关联、DOI+arXiv
  双强关联和无结果，未把弱证据冒充官方代码。
- IEEE Access 保存规则的首次窗口与两天重叠窗口各返回 20 条，重叠 DOI 均识别为已见；索引日期可能
  对应旧年份论文，因此不能表述成“最新发表”。
- 十条本地排序样本暴露并修正日期权重过高，目标论文最终因标题关注词完整命中排第 1。

真实验收不保证任何来源全量覆盖；摘要、源码或开放版本缺失必须保持可见缺失。

## 已知限制与收口

R1 核心完成结论成立，但开始下一主线前仍需一次不扩展功能的一致性修正：

1. F2 UI 当前最多选择 20 条，而 API/旧文档曾允许 50 条，应统一真实上限。
2. 工作区切换应立即清除旧排序，局部加载失败不得显示上一工作区的规则或简报。
3. 补 `candidate_ai_runs` 启动恢复直接测试、简报失败历史和跨工作区离线浏览器断言。
4. 架构的启动恢复清单应明确包含候选 AI 运行。

以上完成并通过既有全套验证后，R1 进入维护状态。新增论文来源、自动调度或更大批量 AI 必须由新的
真实用户问题触发，不能继续沿 R1 编号堆叠。
