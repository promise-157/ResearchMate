# ResearchMate 产品规格

## 产品定义

ResearchMate 是一个本地优先的个人资料采集、理解和行动工作台。它把文字、用户图片、公开网页和具名公开来源转化为可追溯、可检索、可关联的资料项，并通过领域模板支持论文研究、求职管理、Debug 知识沉淀等任务。

它不是论文专用工具、云盘、网站镜像器、万能爬虫或只会聊天的知识库。

## 核心流程

```text
已有资料：导入 -> 提取 -> 去重 -> 分类 -> 用户确认 -> 整理/分析
没有资料：搜索/来源同步 -> 候选箱 -> 提取 -> 筛选 -> 正式入库
```

“候选”与“正式资料”必须分开，避免搜索噪声直接污染工作区。

## 保存原则

- 保存能够支持检索、判断和后续行动的最小必要信息及来源。
- 论文默认保存标题、作者、摘要、分类、日期、代码链接和来源，不下载 PDF。
- 公开网页默认保存提取后的必要文本、结构化字段和 URL，不镜像整站或下载附件。
- 用户主动导入的图片需要保存本地原件，因为图片本身是输入证据；同时保存 OCR 和结构化结果。
- 原始事实、确定性提取、AI 推断和用户确认是不同数据层，不能相互覆盖。

## 通用资料能力

每个资料项应支持：

- 类型、标题、可分析文本、摘要和来源；
- 工作区、标签、自定义字段和处理状态；
- 精确重复、近似文本和语义相似关系；
- 用户备注和用户确认值；
- 提取/AI 运行记录及输入范围；
- 用户明确接受的确定性提取值；接受值独立于原始正文和运行历史，并可被显式选入搜索或 AI 范围；
- 导出和可追溯来源。

用户可以把 1–20 条明确选择的资料组织为当前工作区的“行动专题”。专题保存有序证据清单、任务目标、用户笔记/结论、明确下一步和进行中/已完成/已归档状态；它引用资料但不改写来源事实、提取结果或用户确认层。后续 AI 只能在用户确认的专题证据范围内生成建议，不能替代用户笔记和行动状态。

## 领域模板

- 论文：作者、摘要、方法、技术、代码、是否精读。
- 求职：公司、岗位、地区、薪资、技能、年限、投递状态。
- Debug：错误、环境、假设、尝试、结果、根因和最终方案。
- 通用：不强迫进入某个领域，允许标签和自定义字段。

模板只定义字段、视图和工作流，不复制底层存储与导入逻辑。

当前 Debug 与求职模板都使用本地行标签规则生成确定性提取值，并允许用户另存确认值；确认值优先展示和筛选，重新提取不会覆盖确认。求职模板只整理用户导入的招聘描述，不自动访问招聘网站、操作账号或投递。

## AI 的角色

AI 是核心能力，但必须可控：

- 入库：类型建议、摘要、标签和结构化字段提取；
- 整理：相似资料判断、聚类、关联和信息缺口建议；
- 使用：选中资料的比较、问答、趋势分析和行动建议；
- 复用：从历史求职或 Debug 资料中寻找相似案例。

外部 AI API 是默认的增强路径，DeepSeek 等具名服务商和自定义 OpenAI-compatible 接口由用户配置；调用必须明确展示资料范围，并记录服务商、模型、时间、输入资料 ID、提示词版本、用量、结果和脱敏错误。Key 保存默认使用不落盘的安全模式；设置页也可由用户明确选择便利模式，在展示明文风险和路径后写入已忽略的本机 `config.yaml`，并提供立即删除入口。本地模型只作为用户自行安装的可选隐私后端，ResearchMate 不捆绑 Ollama、不自动下载模型或常驻占用推理资源。

## 互联网发现边界

按风险从低到高支持：用户提供 URL、公开 API/RSS、正常搜索服务、浏览器手动保存当前页面、具名网站适配器、受控定时更新。

默认禁止绕过登录、付费墙、CAPTCHA、robots、访问控制或限流；不自动操作招聘账号、提交表单或投递。条款不清晰的网站优先采用“用户正常浏览后手动保存文字/截图/当前页”。

## 第一版完成标准

第一版必须形成真实闭环：

1. 创建或切换工作区。
2. 导入文字，随后支持图片和公开 URL。
3. 本地清洗、指纹去重和初步类型建议。
4. 用户确认后保存、搜索、筛选和改变状态。
5. 对明确选中的资料运行可审计 AI 分析。
6. 现有 arXiv 摘要同步作为论文领域适配器继续可用。
