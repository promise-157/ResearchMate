> 2026-07-24 | ✅ 已确认

---

## 核心理念

一个 **AI 辅助论文筛选工具**：

```
你导入感兴趣的期刊网址 → 选范围、爬摘要 → AI 逐篇分析 + 整体点评
→ 卡片列表浏览 → 感兴趣的加购物车 → 导出购物车清单
```

---

## 一、启动方式

```
python run.py → FastAPI 启动 → 自动打开浏览器 → Ctrl+C 退出
```

### 3.2 四个核心区域

#### 区域一：爬取控制区

| 元素 | 说明 |
|------|------|
| 期刊源列表 | 每行：复选框 + 名称 + 上次爬取时间 + 上次新增数量 |
| 爬取模式 | 仅新论文（默认，对比 URL 去重）/ 全部重新爬取 |
| 添加按钮 | 弹出输入框，填入期刊 URL + 可选备注名 |
| 爬取按钮 | 显示"爬取已选的 N 个源"，点击后显示进度 |

**去重逻辑**：每次爬取记录论文的唯一标识（arxiv_id 或 paper_url），下次同一期刊源只抓新出现的。

#### 区域二：AI 本批点评

爬取完成后自动生成，调用一次 AI 汇总分析本批所有摘要：

- **基本统计**：爬了几篇、几个源、多少有代码
- **热门方向**：这批论文集中讨论哪些主题
- **推荐关注**：AI 认为最有价值的 2-5 篇，各一句话理由
- **技术趋势**：高频出现的技术/方法关键词
- **可折叠**，默认展开

#### 区域三：论文卡片列表

每篇论文一张卡片。**这是最影响使用体验的部分，仔细设计**：

## 四、论文卡片：词条显示决策

经过权衡，最终决定每条论文卡片展示以下信息：

### 始终显示（紧凑扫描）

| 词条 | 原因 |
|------|------|
| **标题** | 核心，大字，不可省略 |
| **第一作者 + et al.** | 快速识别人物 |
| **期刊/会议 + 年份** | 判断来源质量和时效 |
| **arXiv ID** | 唯一标识，方便搜索 |
| **🔗 有无代码** | 亮点，一眼可见（绿色=有，灰色=无） |
| **💡 创新点（前2行）** | AI 提炼的精华，最核心决策依据 |
| **🛠 技术标签（前3个）** | 快速判断是否与自己的方向相关 |

### 点击展开后显示

| 词条 | 原因 |
|------|------|
| 完整 AI 创新点描述 | 可能需要更多上下文 |
| 全部技术标签 | 可能有遗漏的关键词 |
| 原始摘要 | 用户可自行判断 AI 分析是否准确 |

### 不放的字段

| 字段 | 原因 |
|------|------|
| PDF 链接 | 我们不下载 PDF |
| 引用数 | 爬不一定会拿到，且对筛选帮助不大 |
| 全文 | 没必要，摘要够了 |
| 全部作者 | 太占空间，详情弹窗里再看 |

## 七、数据模型

```sql
-- 期刊源（用户自行添加）
CREATE TABLE journal_sources (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    url TEXT NOT NULL,
    label TEXT,                    -- 用户自定义名
    last_crawled_at TIMESTAMP,
    last_paper_count INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 论文
CREATE TABLE papers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    source_id INTEGER REFERENCES journal_sources(id),
    title TEXT NOT NULL,
    authors TEXT,                  -- JSON 数组
    abstract TEXT,
    journal_name TEXT,
    publish_year INTEGER,
    arxiv_id TEXT UNIQUE,
    paper_url TEXT,
    has_code BOOLEAN DEFAULT 0,
    code_url TEXT,
    ai_innovation TEXT,            -- AI: 创新点
    ai_technologies TEXT,          -- AI: 技术标签 JSON
    ai_analyzed BOOLEAN DEFAULT 0,
    in_cart BOOLEAN DEFAULT 0,     -- 购物车
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 爬取记录（用于去重和点评追溯）
CREATE TABLE crawl_sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sources TEXT,                  -- JSON，本次爬了哪些源
    paper_count INTEGER,
    ai_review TEXT,                -- AI 本批点评全文
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 八、API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET/POST/DELETE | `/api/journals` | 期刊源 CRUD |
| POST | `/api/crawl` | 触发爬取，body: `{source_ids: [1,3,4], mode: "new"}` |
| GET | `/api/crawl/status` | 爬取+AI分析进度 |
| GET | `/api/papers` | 论文列表 `?q=&has_code=&in_cart=&source_id=&page=&sort=` |
| GET | `/api/papers/:id` | 论文详情 |
| PATCH | `/api/papers/:id` | 更新论文 `{in_cart: true}` |
| GET | `/api/cart` | 购物车论文列表 |
| GET | `/api/cart/export?format=csv` | 导出购物车 |
| GET | `/api/sessions` | 历史爬取记录（含点评） |
| GET | `/api/stats` | 首页统计（总论文数、购物车数等） |
| GET/PUT | `/api/settings` | 全局设置 |

## 十、设计总结

| 设计决策 | 理由 |
|----------|------|
| 论文卡片优先紧凑 | 用户要扫 40+ 篇，信息密度比美观更重要 |
| AI 分析默认折叠到 2 行 | 够判断了，想看全文再展开 |
| 技术标签只显示 3 个 | 太多了反而干扰，3 个够判断是否相关 |
| 购物车而非"收藏夹" | 购物车暗示"暂存，后续要处理的" |
| 期刊源去重不删旧数据 | 保留历史数据可以做对比分析 |
| 新增 crawl_sessions 表 | 每次爬取有记录，AI 点评可以回溯 |
